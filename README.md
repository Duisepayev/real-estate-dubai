# real-estate-dubai

## Мониторинг distress-сделок

Каждые 2 часа GitHub Actions проверяет Property Finder (и Threads, если есть токен),
сравнивает цены с зарегистрированными сделками Dubai Land Department и присылает
уведомление в Telegram и/или на e-mail.

### Как это устроено

| Шаг | Что происходит |
|---|---|
| Расписание | `.github/workflows/monitor.yml`, cron `17 */2 * * *` (UTC). Расписание работает только из ветки `main`. |
| Property Finder | Страницы поиска «новые сначала» по каждому району (`config.yaml → searches`). Каждый запуск — 1–2 страницы, раз в сутки — полный обход для отслеживания цен и снятых объявлений. Пауза 2,5 с между запросами. |
| Сделки DLD | Открытые данные DLD (`gateway.dubailand.gov.ae/open-data/transactions`): продажи жилья за 12 мес., догрузка последних 3 недель каждый запуск. Хранятся в кэше Actions (`data/dld.db`), пересобираются, если кэш пропал. |
| Оценка | Проект из объявления (башня/сабкомьюнити) сопоставляется с проектом DLD; берутся сделки того же проекта, той же спальности и типа, площадь ±25%. Диапазон = 25–75-й перцентиль цены за м² × площадь, дисконт — к медиане. Цены других объявлений — отдельно, как ориентир. |
| Вердикт | `target`: дисконт ≥ 20% при ≥ 3 сделках. `review`: дисконт есть, но сделок мало, или 12–20% с признаками срочности. `suspect`: дисконт ≥ 40% — вероятна ошибка, неполная цена или off-plan с долгом застройщику. Остальное не присылается. |
| Дубли | Одно и то же помещение от разных агентов склеивается по ключу «здание + спальни + тип + площадь». Повторное уведомление — только при изменении цены ≥ 2% или повышении оценки. |
| Состояние | `state.db` (объявления, история цен, отправленные уведомления) хранится в отдельной ветке `monitor-state`. |
| Threads | Официальный Threads API `keyword_search`. Без App Review по `threads_keyword_search` ищет только собственные посты владельца токена. |

### Секреты (Settings → Secrets and variables → Actions)

- Telegram: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`.
- E-mail (например, Gmail с паролем приложения): `SMTP_HOST=smtp.gmail.com`, `SMTP_PORT=465`, `SMTP_USER`, `SMTP_PASSWORD`, `ALERT_EMAIL_TO`.
- Необязательно: `THREADS_ACCESS_TOKEN`; `MONITOR_CONFIG_JSON` — JSON, перекрывающий `config.yaml` (например, бюджет, если не хочется держать его в публичном репозитории).

### Ручной запуск

Actions → distress-monitor → Run workflow: `test-notify` — тестовое сообщение, `run` — проверка.
Локально: `pip install -r requirements.txt && python -m monitor run --dry-run --verbose`.

### Ограничения

- У Property Finder нет публичного API для покупателей; используются публичные страницы поиска. Их структура может измениться — тогда запуск упадёт, и GitHub пришлёт письмо о сбое.
- В данных DLD нет корпуса, этажа и вида; сопоставление проекта нечёткое и показывается в уведомлении.
- Первый боевой запуск сохраняет текущие объявления как базу и не рассылает их (иначе придёт сразу много сообщений).
- В публичном репозитории GitHub отключает расписание после 60 дней без активности в репозитории.
